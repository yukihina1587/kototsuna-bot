# OBS 連携設定

ことつな！は OBS WebSocket と連携し、配信の開始・終了やシーン切り替えに応じて BOT を自動制御できます。

---

## 事前準備

### OBS WebSocket を有効にする

1. OBS を起動し、メニューバーの **「ツール」→「WebSocket サーバー設定」** を開く
2. **「WebSocket サーバーを有効にする」** にチェックを入れる
3. ポート番号（デフォルト: `4455`）とパスワードを確認・設定する
4. **「OK」** で保存

> OBS 28 以降は WebSocket サーバーが標準搭載されています。それ以前のバージョンでは [obs-websocket プラグイン](https://github.com/obsproject/obs-websocket) を別途インストールしてください。

---

## 接続設定

ことつな！の設定パネルから **「OBS連携」** を開き、以下を設定します。

| 項目 | 説明 | デフォルト |
|------|------|-----------|
| **OBS連携を有効にする** | 連携機能のオン/オフ | オフ |
| **ホスト** | OBS が動作している PC の IP アドレス | `127.0.0.1` |
| **ポート** | OBS WebSocket のポート番号 | `4455` |
| **パスワード** | OBS WebSocket に設定したパスワード | （空欄） |
| **監視間隔(秒)** | 配信状態の確認頻度（0.2〜10 秒） | `1.0` |

設定を入力したら **「接続設定を保存」** ボタンを押してください。

> **同じ PC で動かしている場合**はホストを `127.0.0.1` のままで問題ありません。別の PC の OBS に接続する場合は、その PC のローカル IP アドレスを入力してください。

## 自動制御

「自動制御」セクションで、配信状態に応じた BOT の自動起動・停止を設定できます。

### OBS連動の自動制御（マスタースイッチ）

このスイッチをオンにすると、以下のチェックボックスが有効になります。オフにすると、配信状態が変わっても BOT は自動で操作されません。

### 配信開始時にBOTを自動起動

OBS の配信が開始されると、ことつな！が自動的に BOT を起動します。

- すでに BOT が起動中の場合は何もしません
- ことつな！が起動していれば、OBS を先に操作しても問題ありません

### 配信終了時にBOTを自動停止

OBS の配信が終了すると、BOT を自動的に停止します。

## シーンルール

OBS でシーンが切り替わったときに、自動で実行するアクションをシーンごとに設定できます。

### 設定できる内容

| 項目 | 説明 |
|------|------|
| **シーン名** | OBS のシーン名（大文字小文字は区別しない） |
| **TTSミュート** | このシーン中は TTS 読み上げをミュートにする |
| **表示ソース** | このシーンに切り替わったとき、指定したソースを表示にする |
| **非表示ソース** | このシーンに切り替わったとき、指定したソースを非表示にする |

### ルールの追加手順

1. **「シーン名」** に OBS のシーン名を正確に入力する（例: `休憩`）
2. 必要に応じて **TTSミュート** をオンにする
3. **表示ソース** / **非表示ソース** に OBS のソース名をカンマ区切りで入力する（例: `翻訳テロップ, カメラ`）
4. **「＋ ルールを追加」** ボタンを押す

### 設定例

| シーン名 | TTSミュート | 表示ソース | 非表示ソース |
|---------|-----------|----------|------------|
| `休憩` | オン | — | `翻訳テロップ` |
| `ゲーム` | オフ | `翻訳テロップ` | — |
| `雑談` | オフ | `翻訳テロップ, カメラ` | — |

## 動作の仕組み

- OBS WebSocket の **イベント購読**（リアルタイム通知）を優先して使用します
- イベント購読に失敗した場合は、**ポーリング**（定期確認）に自動でフォールバックします
- 監視間隔はポーリング時とイベント接続確認の両方に使用されます

---

## うまく接続できない場合

- OBS が起動していることを確認する
- OBS の WebSocket サーバーが有効になっているか確認する（ツール → WebSocket サーバー設定）
- ポート番号とパスワードが一致しているか確認する
- ファイアウォールがポート `4455` をブロックしていないか確認する
- 詳しくは [トラブルシューティング](Troubleshooting) を参照
