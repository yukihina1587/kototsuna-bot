# プライバシーポリシー / クラッシュレポートについて

ことつな！は、不具合の早期発見と修正のために**任意で**クラッシュレポートを開発者に送信する仕組みを備えています（Sentry を使用）。

このページでは、何が送信され、何が送信されないか、どうやって有効化／無効化するかを説明します。

## オプトイン制 — デフォルトは「送信しない」

クラッシュレポートの送信は**完全にオプトイン**です。

- 初回起動時に確認ダイアログが表示されます
- ユーザーが明示的に「送信する」を選ばない限り、何も送信されません
- 「送信しない」または「あとで決める」を選んだ場合、クラッシュ情報はお使いの PC のローカルログにのみ残ります

## ✅ 送信される情報

クラッシュレポートを有効化した場合、以下の情報が Sentry を経由して開発者に送信されます。

| 項目 | 例 |
|---|---|
| 例外の型・メッセージ | `ZeroDivisionError: division by zero` |
| スタックトレース | ファイル名・行番号・関数名（ローカル変数の値は送信しません） |
| アプリのバージョン | `kototsuna@1.9.0` |
| 実行環境 | OS 種別、Python のバージョン、`production` / `development` の区別 |
| イベント発生時刻 | UTC タイムスタンプ |
| 直前のログ（breadcrumbs） | 直近 50 件の INFO 以上のログ。送信前にシークレットマスク処理を実施 |

## ❌ 送信されない情報

以下の情報は **`before_send` フック**で送信前に除去または伏せ字に置換されるため、Sentry 側に届きません。

- **チャンネル名・配信者名・視聴者名**
- **コメント本文・チャットメッセージ**
- **OAuth トークン・アクセストークン**（`oauth:***` のように伏せ字）
- **パスワード・API キー** などの認証情報
- **メールアドレス・IP アドレス**
- **音声認識で取得した発話内容**

実装は [src/sentry_init.py](https://github.com/yukihina1587/kototsuna-bot/blob/main/src/sentry_init.py) の `_scrub_event` 関数にあります。スクラブ対象キーは伏せ字（`***`）に置換され、`oauth:` / `Bearer` / `password=` などの正規表現一致箇所もマスクされます。

## ユーザーフィードバックを送る

エラー発生時に「何をしようとしていたか」を任意で記入できるダイアログが表示されることがあります。記入された内容はそのままクラッシュレポートに紐付けて送信されます。

**ご注意:** ここに個人を特定できる情報や認証情報を**書かないでください**。ユーザーが自由記述する欄のため、自動マスクの対象外となります。

設定パネルの「💬 問題を報告」ボタンからは、クラッシュ無しでも任意のフィードバックを送信できます。

## 設定の変更方法

### 初回起動時のダイアログ
- **送信する**: 即時有効化されます
- **送信しない**: 拒否を保存し、以降ダイアログは出ません
- **あとで決める**: 設定を保存せず、次回起動時に再表示されます

### 設定パネルから変更
1. 右パネルの「設定」を開く
2. 「プライバシー」セクションの「クラッシュレポートを送信する」をオン／オフ
3. **設定変更は次回起動時に反映**されます

## 保存先・保持期間

- 送信先: Sentry（ホスト型 SaaS）
- 保持期間: Sentry の無料プランの規定に準拠（執筆時点で 30 日）
- 開発者は集計済みデータと個別の例外情報を確認しますが、個人を特定する情報は受け取りません

## ローカルログ

オプトインの可否に関わらず、以下のログはお使いの PC 上にのみ保存されます。**送信はされません。**

- `logs/bot_YYYY-MM-DD.log` — 通常ログ（10MB ローテーション、7日保持）
- `logs/bot_YYYY-MM-DD.jsonl` — JSON Lines 形式の構造化ログ
- `kototsuna_error.txt` — 起動時にロガー初期化前にクラッシュした場合のフォールバックログ

サポートが必要なときは、これらのファイルを開発者に直接お送りいただくこともできます（任意）。
